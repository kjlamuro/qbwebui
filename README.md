# qBWebUI

**简体中文** | [English](README.en.md)

面向 qBittorrent 的轻量级自托管 Web 控制台。桌面端与移动端共用同一套代码并自适应布局，**零运行时依赖**（仅使用 Node 内置模块与原生前端技术），单条命令即可启动。

除下载管理外，本项目同时提供媒体封面补全能力：从种子自身目录中提取图片，或通过 TheTVDB 刮削海报与元数据，并按媒体库约定写回种子目录，使 Plex / Jellyfin / Kodi 在下次扫描时即可识别。在移动端通过「添加到主屏幕」可以以全屏独立应用方式运行。

## 功能特性

- **种子列表**：展示名称 / 大小 / 进度 / 下载速度 / 上传速度 / 分享率 / 剩余时间 / 状态，支持点击表头排序；每 2 秒增量刷新，数百个种子仍保持流畅
- **筛选与检索**：全部、下载中、做种中、已完成、已暂停、错误等状态筛选，并支持分类、标签与名称搜索
- **单种子操作**：暂停 / 继续、强制开始、顺序下载、设置分类、重新校验、重新通告 Tracker、删除（可选同时删除文件）
- **批量操作**：多选后统一执行暂停、恢复或删除
- **详情抽屉**：进度环、实时速度、信息页中的平均下载 / 上传速度（取自 qBittorrent 的 `dl_speed_avg`，按种子累计传输量与实际活跃时长计算，切换至信息页时重新拉取）、分块与分享率、文件列表、Tracker 状态。文件列表中的勾选框默认锁定以避免误操作，点击「修改下载列表」后可逐个跳过或恢复；未完成的文件以较低对比度显示，便于区分已完成部分
- **在线预览**：详情页文件列表中的图片 / 视频 / 音频可直接点击文件名查看。图片集支持上一张 / 下一张切换、方向键与移动端左右滑动，并支持滚轮 / 双指 / 双击 / 按钮缩放，放大后可拖动查看细节；视频通过 HTTP Range 分片读取，支持拖动进度条、边下边看以及多文件连续播放；MKV / HEVC / 杜比视界等浏览器无法解码的格式提供「下载 / 新标签打开」作为兜底
- **添加种子**：支持 magnet 链接、HTTP 链接与 `.torrent` 文件（支持拖拽与多选），可指定保存路径、分类、标签并以暂停状态添加；默认停留于「种子文件」页，可在设置中将默认页改为 magnet。选定文件或粘贴 magnet 后会自动执行一次海报刮削，添加完成后自动应用，无需先添加再单独处理封面
- **保存路径历史**：输入框提供下拉目录选择，依次为默认路径、近期使用路径，以及依据种子库统计得出的常用目录（附种子数量）；支持关键词过滤、`↑↓` 键选择与 `↵` 键确认
- **封面缩略图**：当种子拥有独立目录时，自动从该目录中选取图片（优先 `poster` / `folder` / `cover`，其次 `fanart` / `banner`）；无可用图片时回退为类型图标，类型依据目录内文件的**体积权重**判定（视频 / 音乐 / 图片 / 书籍 / 压缩包），而非依据种子名称推测。同时支持手动上传、从目录中选取指定图片，或直接粘贴图片（桌面端 `⌘/Ctrl + V`，移动端点击「粘贴」后长按粘贴框）。单文件种子位于共享下载根目录时不参与目录匹配，以避免误用其他种子的海报。缩略图缓存于 `data/covers/`（macOS 下通过 `sips` 压缩至 640px），可在设置中整体关闭
- **TheTVDB 刮削**：依据种子内的正片文件名（无法获取时使用种子名）识别「片名 + 年份 + 季数」，在 [TheTVDB](https://www.thetvdb.com) 检索匹配的剧集或电影并下载海报；支持自动匹配，也支持从检索结果中人工选择（左侧列表、右侧简介），随后选择具体海报。优先级为：手动上传的图片 > TheTVDB 海报 > 目录内图片 > 类型图标。设置中可开启「新加入的影视种子自动刮削」，也可对列表中全部影视种子批量刮削（带进度条，可中途停止）
- **写入媒体库**：刮削成功后，海报与 NFO 按媒体库约定写入种子自身目录——电影为 `视频名-poster.jpg` + `视频名.nfo`，剧集为 `poster.jpg` + `tvshow.nfo`。Plex / Jellyfin / Kodi 扫描后即可获得封面、原名、年份与简介；放弃刮削或清空 TheTVDB 缓存时会一并删除
- **列表标题三档显示**：仅显示原始文件名、以媒体名为主（原名为副）、以原名为副（媒体名为主），可按偏好切换
- **设置面板**：连接地址、全局限速、添加种子默认方式、主题与刷新频率、缩略图开关、封面缓存清理、TheTVDB 刮削配置、界面更新检查；移动端以全宽底部抽屉呈现
- **全局状态**：上下行速度、剩余空间、累计流量、全局限速、备用速度限制
- **速度趋势图**：桌面端侧边栏底部与移动端「概览」页各提供一条近 5 分钟的上下行趋势曲线。采样在服务端完成（每 5 秒一次，可通过 `QBWEBUI_SAMPLE_MS` 调整），刷新页面或重启服务均不会从零开始；中途断档以两段独立曲线呈现，不以直线拟合。详情页信息卡中的「峰值下载 / 峰值上传」取自同一套采样记录的最大值
- **外观**：支持深色 / 浅色 / 跟随系统；桌面端为侧边栏 + 表格，移动端为卡片 + 底部导航；可通过「添加到主屏幕」以应用形式运行
- **桌面端侧边栏可收起**：顶栏最左侧的面板图标（侧栏展开时显示为强调色）可将 268px 侧栏收起，将宽度让给列表；收起状态记录在本地。收起后状态筛选自动转为顶栏下方带数量的 chips，分类与标签展开侧栏即可访问
- **中英双语**：通过顶栏地球图标或「设置 → 外观 → 语言」在中文与 English 之间切换；首次访问按浏览器语言自动选择，之后记忆选择结果。文案全部存放于 `public/i18n.js`，以中文原文作为 key，缺失译文时回退为中文而不会暴露原始 key
- **封面缓存**：设置中展示扫描条目数与图片占用空间，可清空扫描缓存（重新扫描目录）或全部封面缓存（包含手动上传的图片）

## 快速开始

环境要求：Node.js ≥ 18，以及一个已启用 Web UI 的 qBittorrent（4.x / 5.x 均可）。

```bash
git clone https://github.com/kjlamuro/qbwebui.git
cd qbwebui
node server.mjs        # 或 npm start
```

```
本机访问   http://127.0.0.1:7788
局域网访问 http://192.168.x.x:7788   ← 移动端使用此地址
```

macOS 下也可直接双击 `start.command`：服务在后台启动，浏览器自动打开，启动完成后终端窗口可以直接关闭。要停止请双击 `stop.command`。

### 后台运行与开机自启

macOS 下有两种方式，按需选择：

| 方式 | 优点 | 局限 |
|---|---|---|
| `start.command` | 双击即用，日志写入 `~/Library/Logs/qbwebui.log` | 进程崩了不会自动重启 |
| `install-autostart.command` | 开机自启、崩溃 10 秒内自动重启、完全脱离终端 | 需执行一次安装 |

> **为什么仅靠 `nohup` 不够**：Node 启动时会重置信号处理，把 `nohup` 设置的 SIGHUP 忽略覆盖掉，所以 `nohup node server.mjs &` 在关闭终端时依然会被带走，而且不留任何日志。`server.mjs` 中显式注册了 `SIGHUP` 处理，才能真正挡住关窗口。这也是服务"无声消失"最隐蔽的原因。

安装开机自启后，卸载命令：

```bash
launchctl bootout gui/$(id -u)/com.kjlamuro.qbwebui
```

### 仅预览界面

无需安装 qBittorrent，可使用内置的模拟数据运行：

```bash
npm run demo           # http://127.0.0.1:7799
```

`tools/mock-qb.mjs` 是一个只读的模拟 qBittorrent 服务，包含 15 个虚构种子，所有操作仅返回成功且不写入磁盘。它会同时生成一套真实文件（含一段可播放的示例视频与一组图片），因此详情页的图片 / 视频预览可直接体验。本文档中的截图均由该脚本生成。

## 配置

优先级：环境变量 > `config.json` > 默认值。

| 配置项 | 环境变量 | 默认值 |
| --- | --- | --- |
| qBittorrent WebUI 地址 | `QB_URL` | `http://127.0.0.1:9898` |
| 本服务监听端口 | `PORT` | `7788` |
| TheTVDB API Key | `TVDB_API_KEY` | 界面中填写（存于 `data/tvdb.json`） |
| TheTVDB 订阅者 PIN | `TVDB_PIN` | 空（多数 key 无需填写） |

```bash
QB_URL=http://192.168.1.10:9898 PORT=7788 node server.mjs
```

qBittorrent 地址仅来源于上述两处，**界面中不提供修改入口**（Web UI 端口需在 qBittorrent 客户端侧调整，随后修改 `QB_URL` 或 `config.json` 并重启本服务）。界面中不再出现同名字段，可避免将「qBittorrent 的 WebUI 地址」与「本页面的访问地址」混淆。

### TheTVDB 刮削

在「设置 → TheTVDB 刮削」中填写个人 API Key（登录 [thetvdb.com](https://www.thetvdb.com) → Dashboard → API Keys，免费额度足以满足个人使用），保存并通过测试后，封面弹窗中将出现刮削区：

- **自动匹配**：优先解析种子**内部的正片文件名**（体积最大的视频文件，跳过 sample 与花絮），仅在无法获取时使用种子名；名称会剥离 `1080p` / `x264` / 制作组 / `S01E02` 等噪音字段，并携带年份发起检索。评分足够高时直接应用其**第一张海报**；置信度不足时将候选结果以列表形式呈现以供选择
- **检索结果左列表右简介**：左侧逐条列出片名 / 年份 / 类型（附小海报），点击任一条目后右侧切换为该条目的**大海报与简介**。同名作品存在多个版本、或剧集与电影混杂时，依据简介判断比依据海报缩略图更为可靠。右侧提供两个按钮：「看它的海报」进入海报网格以选择具体图片，「直接套用第一张」跳过该步骤。从海报页「返回」将回到此前的结果列表（使用缓存，不重复联网）
- **优先使用种子内文件名的原因**：种子名由发布组拼接而成（如 `Some.Release.2024.2160p.WEB-DL.DDP5.1.Atmos-GRP`），而正片文件名通常更为规范（如 `The.Matrix.1999.1080p.mkv`）。`.torrent` 文件可在**添加前**解析（服务端直接读取 bencode，无需等待下载），已添加的种子则通过 qBittorrent 的文件清单获取（未完成下载同样可用）。若正片文件名为 `01.mkv` / `cd1.avi` 等无法识别的形式，将自动回退至种子名
- **中英混排名称的拆分重试**：`痴迷.Obsession.2025`、`求救信号.Mayday.2026` 这类发布名整串提交至 TheTVDB 无法获得结果，因此按「英文段 → 中文段 → 整串」顺序依次尝试，命中足够相似的结果即停止；纯英文或纯中文名称仅检索一次，不额外消耗接口额度
- **中文译名的跨语言码检索**：TheTVDB 上的中文并非单一语言码——较早作品（如《黑客帝国》）挂载于 `zho` 之下，2020 年之后的作品（如《蜘蛛人：重生日》）多数仅挂载 `zhtw`，另有少量 `zhcn`。仅按 `zho` 查询会返回 404，导致整部作品静默降级为英文名与英文简介；因此在选择「中文」后按 `zho → zhtw → zhcn` 依次尝试，命中存在名称的语言码即停止（404 结果同样按语言码缓存，同一作品不重复请求）。代价在于：TheTVDB 上仅有繁体条目的新作品，其名称与简介将显示为繁体
- **打开封面弹窗即自动刮削**：尚未刮削过的种子，在打开「封面•刮削」弹窗时后台已完成匹配并应用第一张海报，同时铺开海报列表，切换海报只需点击一次，全程无需操作「自动匹配」
- **添加种子阶段即可刮削**：选定 `.torrent` 文件（系统将文件提交至服务端以解析其中的正片文件名）或粘贴 magnet 链接（无文件清单，仅能依据 `dn` 参数推测），添加弹窗将立即联网匹配，命中的海报显示在「封面缩略图」中，其下方以与详情页相同的卡片形式铺开该作品的其他海报（附「海报 · 语言」标签），点击即可应用。当无法确定具体作品时，弹窗将临时加宽并呈现**与详情页一致的双栏布局**——左侧为候选列表，右侧为所选作品的大海报、标题、类型年份与简介，并提供两个按钮：「看它的海报」将其全部海报铺开以供挑选，「就用这张」直接使用检索结果中的海报且不再发起请求。也可点击「刮削封面」手动触发；若仍未获得结果，则改用「选择图片」
- **检索关键词可编辑**：检索关键词默认取上述「解析出的片名」——`The.Matrix.1999.1080p.BluRay-GRP` 在输入框中显示为 `The Matrix`，下方以小字注明来源：「按种子里的 The.Matrix.1999.2160p.mkv 认作 The Matrix 1999」或「已从种子名识别为 …」。解析过程中剥离的年份与季数仍会随请求发送，不会因名称清洗而丢失年份。若识别有误可直接修改，输入 `Obsession`、`Sintel` 等规范片名后按 `↵` 或点击「刮削封面」即按新关键词重新检索；已编辑的关键词不会被自动刮削覆盖，连续点击不会被上一次请求阻塞，过期响应将被丢弃
- **手动检索**：封面弹窗中的同一关键词输入框同样可编辑，并可强制按「剧集 / 电影」过滤；结果先以列表呈现，点击一条查看简介，再点击「看它的海报」展开全部海报（支持按语言过滤），点击海报即可应用
- 下载所得海报存放于 `data/covers/tvdb/`，与目录扫描缓存一致，仅在首次时联网；执行「清空自动封面」时将一并清除
- API Key 仅保存在本机 `data/tvdb.json`（已在 `.gitignore` 中）或环境变量中，**不会**打包进仓库。TheTVDB 服务条款将 key 限定为「申请时登记的项目」使用（不可转让），因此本项目不内置任何密钥，由使用者自行填写

> TheTVDB 要求展示其元数据时注明来源，封面弹窗与设置面板中已包含 "Metadata provided by TheTVDB" 链接。海报与元数据的版权归各自权利人所有，TheTVDB 不为图片授权背书，请仅用于个人本地用途。

> 常见配置问题：qBittorrent 设置中的 `连接 → 监听端口`（例如 40459）为 BT 端口，**并非** WebUI 端口。填入 `QB_URL` / `config.json` 的应为 `Web UI → 端口`（例如 9898）。

## 移动端使用

1. 移动设备与主机处于同一 Wi-Fi 网络
2. 访问 `http://<主机局域网 IP>:7788`（服务启动时终端会打印本机与局域网地址）
3. iOS Safari 选择「分享 → 添加到主屏幕」，Android Chrome 选择「添加到主屏幕」，即可全屏独立运行（已配置 `manifest`）

首次打开若弹出登录框，输入 qBittorrent 的用户名与密码；勾选「记住这台设备」后本机将自动登录。也可在 qBittorrent 中将内网网段加入「Web UI → 免验证白名单」（如 `192.168.1.0/24`）。

### iOS / PWA 说明

- 「添加到主屏幕」后以独立应用方式运行：状态栏与底部手势区已按 `safe-area` 适配，深浅色跟随系统
- **登录记忆由服务端保存**（`config.json` 中的 `remember` 字段，已在 `.gitignore` 中）：iOS WebKit 会在连续 7 天无交互后清除网页的 localStorage，密码存于服务端可避免丢失；会话由服务端自动续期，打开即为已登录状态
- 内置 Service Worker：静态壳缓存结合后台更新（stale-while-revalidate），二次打开近乎即时，弱网或离线状态下仍可显示界面骨架；`/api/*` 数据一律直连且不缓存。部署新版本后，下次打开会自动刷新一次
- 移动端输入框统一为 16px，避免 iOS 聚焦时页面自动放大；列表已禁用长按选中与双击缩放
- 移动端所有自底部弹出的抽屉（详情 / 操作菜单 / 概览 / 设置、添加、封面等弹窗）均支持下拉关闭：按住顶部拖拽条或标题栏向下拖动，内容滚动至顶部后继续下拉同样生效；位移超过 88px 或快速甩动即关闭，未达阈值则回弹（第二根手指落下或系统手势打断同样回弹），向上推动仍为正常滚动。登录框不参与该手势（避免误关导致无法使用），确认框下拉等同于「取消」

## 安全说明

- 服务默认监听 `0.0.0.0`，**同一局域网内的其他设备均可访问该页面**。请勿将其暴露至公网；如需远程访问，请通过 VPN 或带鉴权的反向代理实现。
- 「记住这台设备」会将 qBittorrent 账号密码以明文形式存入浏览器 `localStorage`，共用设备请勿勾选。
- 代理仅在内存中持有 qBittorrent 的 SID，不写入磁盘；重启服务后需重新登录。
- 本项目不包含任何用户体系，鉴权完全由 qBittorrent 负责。
- 封面缓存写入 `data/covers/`，其索引中包含**本机磁盘绝对路径**，因此该目录与 `config.json` 一样已在 `.gitignore` 中，不会进入版本库。

## 为什么需要一个本地 Node 服务

浏览器直连 qBittorrent WebUI 会被 CORS 策略拦截，且登录凭证（SID）为 HttpOnly Cookie，前端无法读取。因此 `server.mjs` 仅承担两项职责：

1. 托管 `public/` 目录下的静态页面
2. 将 `/api/v2/*` 反向代理至 qBittorrent，并在**服务端**保管 SID

前端因此只需与同源地址通信，既不存在跨域问题，也无需任何构建步骤。

## 实现要点

- 每 2 秒并发请求 `/torrents/info` 与 `/sync/maindata?rid=`；后者为增量接口，`server_state` **仅携带变化字段**，必须执行合并而非覆盖，否则「剩余空间」会被重置为 0
- 列表采用 keyed DOM diff：仅更新变化的文本与进度，重排通过 CSS `order` 实现
- qBittorrent 的暂停操作为**异步**生效（延迟 1~2 秒），前端先执行乐观更新并保留 2.5 秒窗口，避免状态回弹造成闪烁
- 同时兼容 WebAPI 5.x 的 `stop/start` 与旧版 `pause/resume`，失败时自动切换
- 保存路径下拉使用 `position: fixed` 动态定位，避免被弹窗的滚动容器裁切；下方空间不足时向上展开
- 表格列宽按 4 档 `--row-grid` 分别校准，确保**在该断点最窄宽度下仍可容纳**（可用宽度 ≈ 视口宽 − 268px），否则 901/1041/1181/1281 等交界处会出现溢出，最右侧操作列被裁切
- 操作菜单为同一组件的两套形态：≤900px 时为底部抽屉，>900px 时为居中浮层
- **下拉关闭手势**（`public/app.js` 中的「抽屉下拉关闭」模块）：卡片顶部 64px 区域直接接管（不与内层滚动竞争），内容滚动至顶部后继续下拉同样接管，向上推动则放行给原生滚动；位移每帧仅写入一次（`touchmove` 在一帧内可触发多次，120Hz 设备更为密集），速度取最近 90ms 内的位移（先按住再甩动同样可判定）。遮罩拆分为独立图层并仅修改 `opacity`（纯合成操作），拖拽期间临时关闭其 `transition` 与全屏 `backdrop-filter`，否则每次写入都会重启过渡并重新计算高斯模糊。任何「中途放弃」情形（第二根手指落下、系统 `touchcancel`）均走同一收尾路径，回弹并清除内联样式；抽屉开关时还会再次调用 `resetDrawer`，即使手势层异常也不会残留半透明遮罩
- 仅在种子「拥有独立目录」时才扫描封面（`content_path` 为目录且不等于 `save_path`）；单文件种子直接跳过，避免误用共享下载目录中其他种子的海报
- **类型图标不依据名称推测**：后端扫描种子目录（或向 qBittorrent 请求文件清单），按各类文件的**体积权重**判定主类型（视频 / 音乐 / 图片 / 书籍 / 压缩包镜像），剧集中单张海报的权重不会超过 20GB 正片；前端仅在结果返回前以分类与种子名临时占位
- 目录扫描结果缓存 60 秒，图片统一归一化至 `data/covers/`（原图 → 640px 缩略图），避免外置磁盘因每行缩略图被反复遍历
- 缓存分为两层：**内存 → `scan.json` → 实际磁盘扫描**。下载中的种子 60 秒后重扫，已完成的种子 6 小时后重扫；`scan.json` 采用合并写入，服务重启后仍能命中，次日开机无需重新遍历外置磁盘。设置中可查看缓存概况，并可一键清空扫描结果或全部封面缓存
- 类型结果按**来源**分级缓存，且**独立于目录扫描**：来自种子文件清单的结果永久有效（元数据不变），来自目录扫描的结果有效 30 分钟（已完成的为 6 小时），仅依据名称推测的结果有效 60 秒。因此「存在缓存」不再意味着需要等待——获取类型时不会顺带触发目录扫描
- **添加种子时即写入首次类型**：qBittorrent 在接收种子后立即具备文件清单（元数据不依赖下载进度），因此新种子进入列表时即为正确图标，无需等待目录扫描；仅尚未获取元数据的磁力链接会先以名称或分类临时推测
- 详情页预览直接读取 `save_path`：qBittorrent 的 `files[].name` 为**以保存目录为根**的完整相对路径，多文件种子已包含种子目录名，不可再以 `content_path` 为基准拼接，否则会生成 `目录/目录/文件` 形式的错误路径。下载中的文件会额外尝试临时目录与 `.part` / `.!qB` 后缀；视频通过 206 Partial Content 与 HTTP Range 边读边播，不会将整个文件读入内存或先落浏览器缓存，拖动进度条与边下边看均依赖此机制
- **TheTVDB 刮削在服务端完成**：登录 token（有效期 1 个月）与检索 / 海报列表结果均落盘缓存，同一作品不会重复请求；译名按「语言码」分别缓存（`zho` / `zhtw` / `zhcn` 各自记录 404），调整译名策略时通过 `TR_SCHEME` 整体失效检索缓存，避免旧英文名持续命中。自动匹配引入打分机制（名称归一化完全相等 +100、年份 ±1、剧集 / 电影类型加成），低于阈值时交由人工选择而非强制套用，以避免匹配到同名但无关的作品。中英混排的发布名会拆分为多个查询词依次尝试，命中 70 分以上即停止——这是「自动匹配无结果而手动输入英文却能检索到」的根因，整串 `痴迷 Obsession` 在 TheTVDB 上返回零结果
- **缩略图按需请求**：后端在类型接口中同时返回「该种子是否存在封面」的标记（仅读缓存、不触发扫描），前端仅对标记为「有」的行发起图片请求。缺少该机制时，一屏十余行会各自触发一次 404，外置磁盘还需额外执行一次无谓的 `stat`
- **速度采样在服务端常驻**（`lib/speedlog.mjs`）：浏览器关闭后仍需继续记录，否则曲线始终从「打开的这一刻」开始。采样通过 `/sync/maindata` 增量接口完成，数百个种子仅返回变化的行，不会每 5 秒拉取一次数百 KB 的 `/torrents/info`（仅当增量接口完全未返回种子时退化为每分钟兜底一次）。内存中保留 2 小时的采样点，并每 60 秒落盘至 `speed-history.json`，退出时补写一次，重启后接续；`/__speed?window=` 提供曲线数据，`/__speed/peak?hash=` 提供单个种子的峰值。峰值定义为「5 秒采样所观测到的最大值」，真实瞬时峰值只会更高，界面中亦按此口径标注
- **iOS 独立 PWA 的布局视口高度小于屏幕高度**：从主屏图标启动时，视口顶部紧贴状态栏下沿，`100vh` 与 `fixed bottom: 0` 均无法到达屏幕实际底部（差值恰为顶部安全区高度）。因此贴底元素按 `env(safe-area-inset-top)` 推导 `--icb-deficit` 进行补偿，该补偿仅在「独立模式 + 实测存在缺口」时生效。此外不应使用 `apple-mobile-web-app-status-bar-style`，交由 manifest 的 `standalone` 走现代通道，可规避一整套状态栏几何问题
- **弹窗正文为滚动容器而非可压缩盒子**：`.modal-body` 以 `flex-direction: column` 排布卡片，子项默认 `flex-shrink: 1`，窗口变矮时会优先压缩内容（封面网格中的海报被裁切）而非产生滚动条，因此需显式设置 `flex: 0 0 auto`
- **中文原文即为 i18n 的 key**：`tr('下载中')` 以该中文串查询英文词典，未命中则原样返回，因此缺失译文时会回退为中文而不会暴露 `some.dotted.key`；静态标签通过 `data-i18n` / `data-i18n-text` / `data-i18n-html` / `data-i18n-title` / `data-i18n-placeholder` / `data-i18n-aria` 声明式绑定。`<head>` 中的一小段内联脚本会在首帧绘制前写入 `html[data-lang]` 并隐藏 body，待 `app.js` 完成词典注入后再显示，因此英文用户不会先看到一帧中文；另设 2 秒兜底，确保脚本异常时不会出现白屏。切换语言采用原地重渲染（同时清除 `_v` / `_sig` 等渲染缓存），不刷新页面

## 开发

```bash
npm run demo         # 基于模拟数据运行界面，前端调试无需连接真实 qBittorrent
npm run shots        # 重新生成 docs/ 中的截图（需本机安装 Chrome / Chromium）
npm run shots:en     # 重新生成 docs/en/ 中的英文界面截图
npm run icons        # 由 public/icon.svg 重新生成三份 PNG 图标（需本机安装 Chrome）
npm run check        # 语法检查 + 词典覆盖率检查
npm run i18n         # 仅检查每条界面文案是否具备英文译文
```

前端无打包步骤，修改 `public/` 后刷新即可生效。截图脚本基于 Chrome DevTools Protocol 实现，自行启动一个临时无头实例、按脚本执行点击序列后截图，因此「打开详情抽屉」「检索海报」等界面状态同样可复现。

图标位图请勿手工另存：iOS 的 `apple-touch-icon` 必须满幅不透明（iOS 自己会套圆角遮罩，自带圆角会在四角露出白底），manifest 的 `any` 版本保留自绘圆角，Android 的 `maskable` 版本还要把图案收进中间安全区。三者处理方式不同，统一由 `npm run icons` 生成。
